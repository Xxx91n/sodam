# 托盘点击交互规范

- 状态：accepted
- 日期：2026-10-20
- 关联：Issue #19 / comment 6282060892；ADR-0001
- 决策来源：本轮 grill 账本 D-001 ~ D-005（归档于 `.scratch/archive/2026-10-20-tray-click/`，不入库）
- 实现交接：`.scratch/tray-click/handoffs/next-round.md`（不入库）

## 1. 范围

本规范覆盖托盘图标的鼠标点击交互，以及点击后主窗口的状态。不覆盖关闭按钮语义、托盘菜单内容变更、窗口几何持久化与其他鼠标手势。

## 2. 平台行为（D-001）

| 平台 | 左键 | 右键 |
| --- | --- | --- |
| Windows | 单击聚焦/唤起主窗口 | 打开快捷菜单 |
| Linux | 保持现状：单击聚焦/唤起主窗口 | 打开快捷菜单 |
| macOS | 打开快捷菜单（保持现状） | 打开快捷菜单（保持现状） |

约束：

- 不要求三端行为一致。
- macOS 左键不得改为聚焦/唤起。
- Linux 只做防回归，不改变现有交互。

## 3. 左键点击语义（D-002）

适用于 Windows 与 Linux：

- 左键单击立即聚焦/唤起主窗口。
- 双击不定义独立行为；第二次点击只做幂等的再次聚焦。
- 主窗口已在前台时再次点击不隐藏、不最小化。
- 不为区分双击引入延迟或双击判定。
- 双击不承担开窗职责。
- macOS 左键按第 2 节保持菜单。

## 4. 快捷菜单（D-003）

- 三端菜单保持现有结构。
- 保留「显示主窗口」项。
- 保留「正在播放」行；有曲目时可点击并发起「显示主窗口」。
- 不因左键接管而删除菜单开窗入口。
- 不把「正在播放」行改为纯信息行。
- macOS 菜单必须保留开窗入口，与 D-001 的兜底配套。

## 5. 唤起后的窗口状态（D-004）

唤起路径严格复用 `show_window`：

| 当前状态 | 行为 |
| --- | --- |
| 最小化 | 还原并聚焦 |
| 已关闭到托盘 | 重建主窗口；沿用同一个 Root；页面、队列、播放状态不重置 |
| 已在前台 | 无操作（no-op） |

约束：

- 不降级为「只处理已存在窗口」。
- 重建时不重置 Root。
- 不主动跨显示器/虚拟桌面搬移窗口。
- 单实例二次启动继续走同一 `show_window` 路径。

## 6. 重建窗口几何（D-005）

- 重建主窗口沿用现有 `main_window_options`：980×640、主屏居中、最小 900×560。
- 不恢复上次位置/尺寸。
- 不新增窗口几何持久化。
- 不因显示器/DPI 变化引入额外分支。

## 9. 显式范围外

- 三端硬性统一（D-001 负向）。
- macOS 左键改为聚焦/唤起（D-001 负向）。
- Windows/Linux 左键 toggle、双击独立行为、为区分双击引入延迟（D-002 负向）。
- 删除菜单开窗入口、把「正在播放」行改为纯信息行（D-003 负向）。
- 只处理已存在窗口、重建时重置 Root、主动搬移窗口（D-004 负向）。
- 恢复或持久化窗口几何（D-005 负向）。
- 中键/长按等其他手势、关闭按钮语义：未进入本轮账本，不属于本规范；如需变更另行开题。
