# 播放链路失败分类落在本仓库，签名服务可用性不在承诺范围内

一次播放尝试串联了四个阶段：地址解析、签名、音频体传输、解密落盘。其中签名由
`libmssdk` 服务完成——它不是我们的依赖，而是全体 SodaM 用户共享、由项目自己运维的一台
外部 HTTP 服务（默认明文 HTTP，待签请求头可能包含 Cookie）。现状是所有失败都被压成一句
`下载失败`，且固定重试 3 次，于是永久性失败也在重复打扰那台共享服务。

我们决定：由 `sodam-core` 产出具名错误类型 `PlaybackFailure { stage, retryability, action }`
（手写 `Display`/`Error`，不引入 `thiserror`），分类逻辑写成可离线单测的纯函数；重试预算收敛为
单层——按失败分类决定要不要再试、并用尝试次数封顶，**不设总墙钟时长**（那等于把刚从上游拆掉的
「整首下载总时限」从另一侧装回来，会误杀慢但仍在推进的传输）；签名与鉴权类失败视为不可重试，一个播放
尝试内最多调用签名服务一次；错误文本在本仓库就地 redact 到首个 `?`，不等上游改动。
理由是只有串联这些调用的那一层知道失败发生在哪个阶段，而 UI 侧需要对不同失败做不同的事——
这是具名 enum 而非 `anyhow::Context` 的判据。

「无进展时长」这个更对的判据我们**暂时接不上**，不是没想到：S1 里没有任何可观测的下载进度——
`download_to_cache` 是一次阻塞调用，失败就把 `.part` 删掉，跨尝试零进度。等阶段二有了密文暂存与
`Range` 续传、字节偏移第一次成为可读进度，才谈得上按「多久没有新字节落盘」来判放弃。

下载进展不可观测，不等于**播放**进展不可观测。播放位置一直在 `PlaybackSnapshot` 里，所以连败
封顶的**复位**判据用它：装载完成不清零，播出去若干秒才算缓过来。理由是「能装载、不出声」的坏文件
会把连败永远压在阈值下，封顶形同不存在；而熔断复位的规范语义（Circuit Breaker 的半开态要连续成功）
本来就要求确认成功，不是确认尝试没报错。放弃判据仍然只用尝试次数与失败分类——播放位置对「这一次
取流有没有推进」毫无发言权，那条要等阶段二。

落闸这个动作必须同时暂停引擎并拦住自动续播：只写界面的 `playing = false` 拦不住出声，也拦不住
播完翻下一首，「已暂停」于是成了谎话（真机踩到）。

**中途停住不计入连败**。Media3 的 `STATE_BUFFERING`、GStreamer 的 `BUFFERING` 消息、AVPlayer 的
`waitingToPlayAtSpecifiedRate`、mpv 的 cache 自暂停，四方官方文档一致把「已经在放但数据跟不上」
建模成状态而不是 error；只有终止性错误才算一次失败尝试。把 rebuffer 计入预算，是弱网下播放器
连环跳歌后「自我了断」的经典成因。

## Status

accepted

## Considered Options

- **只在 UI 侧从错误字符串推断分类**：被否。它把类型信息烧成一句文案，是脆弱的隐式契约。
- **等上游把 `SodaError::Http(String)` 拆成带相位的变体再动手**：被否。那会让已经能止血的半轮
  修复去等一个排不出日期的跨仓库 review。
- **给签名服务加令牌桶式重试配额**：被否。我们要的是"少打扰共享服务"，不是模式切换机器。

## Consequences

- 阶段归因存在明确上限：签名失败的错误形态与元数据接口同为无相位的 `Http`/`Json` 变体，
  因此本仓库当前只能报到「地址解析（含签名）」这一粒度。**「签名」要单列是上游 libresoda 的
  职责**，不在本决定的承诺内。
- 更根本的是：签名/权益失败在多数路径上**不产生错误**。上游在 PC 接口失败后会回落成
  `Ok(试听片段)`。因此本决定同时声明：**降级为试听不是失败**，它属于另一个维度
  （实际音质与请求意图的落差），不得伪装成 `PlaybackFailure`，否则重试预算与文案两条线都会错位。
- 我们不在用户可见文案里写「检查签名服务」这类对方没有操作杠杆的话；可操作的出口只有设置页的
  签名服务地址/Token，或在本机运行 `libmssdk`。
- 失败后**要不要换一首**由修复动作决定，而不是由「它是不是错误」决定：下架与网络抖动可以换
  （队列里还有别的歌）；登录、签名服务、权益、磁盘则停下——换一首也一样失败，
  连续跳过会把一个全局故障伪装成「这几首运气不好」。
- 签名服务的可用性、延迟、TLS、鉴权与共享容量不在本仓库的可修范围内（见 backlog 中跨仓库条目）。
