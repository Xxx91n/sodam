# 音质偏好只存意图，实际档位由服务端决定

用户在设置里把音质选成「自动」，登录后它被写成一个具体档位（VIP → `lossless`）。之后会员到期
或换号，档位不再跟着变，看起来像设置失效了，界面上却没有任何迹象说明发生了什么。同一个字段
里还混着「用户选的」和「程序写的」两种来源，而盘上一模一样，事后无法区分。

我们决定：**配置里的音质字段只表达意图**——`auto` 或一个具体档位。实际拿到哪一档由服务端按
账号权益与曲目可用性决定，每次取流时现算，不落盘。

**删掉按会员等级推导档位的逻辑。** `Session::refresh_quality` 与 `auto_quality_for` 一并删除，
登录后不再改写音质配置。理由是客户端维护「账号等级 → 最高档位」这张表会滞后于服务端：调研过的
客户端（Sonora、InnerTune、Navidrome、Spotify、TIDAL）都把权益门禁放在服务端，客户端自己加的上限
是单向阀，只会往下压。代价是客户端不再预测「VIP 应该给到什么」，但这本来就是服务端的判断。

**已有配置值一律不动。** 用户手选的档位与旧版本写进去的档位在盘上完全一样，无法区分。
所以不重置、不改写，只在设置页给一句提示（「若不是你选的，点「自动」即可恢复跟随账号权益」）
和一个回到「自动」的入口。空串是历史写法，读作 `auto`；新写入一律写 `auto`，让「自动」在配置里
只有一种写法。

**意图与实际分成两个可见面。** 设置页只讲意图，不显示任何「当前实际」的数字——那是某一首歌的
事实，全局页面切歌就过期。实际档位由播放条徽章显示，徽章本身变成档位菜单的入口：勾选的是意图，
显示的是事实。

**切线从下一首生效，当前曲不重载。** 中途断开已取到的流不划算，主流客户端也不这么做；界面在切档
时说明「从下一首生效」，下一首的徽章变化就是生效的证据。

**降档如实说出两侧，不猜原因。** 实际档位低于所选时，徽章做视觉区分并在装载完成时写一行状态行
（所选 X，实际 Y）。不区分原因：取流那一段在「账号没有权益」与「这首没有该档位」两种情况下
返回值相同，也没有字段能把二者分开，猜一个原因就是向用户断言查不到的事。

**缓存按意图命名，边车记实际档位。** 缓存文件名带的是意图标签，所以「自动」下同一首歌始终命中
同一个文件——权益升级后仍会先播到非会员时期缓存的档位，直到清空缓存或换意图。边车新增一个字段
记录实际档位分数；缺这个字段的旧文件视为未知，既不标记降档也不触发重新下载。降档是**每次读取时
现算**的，不写回缓存——否则用户改了意图，缓存里的旧结论就变成假话。

**详细日志的开关进配置。** 设置页「诊断」增加一个布尔开关，打开后把六个话题都提到 `DEBUG`。
它与环境变量是并集：两边都只能「记更多」，不存在谁覆盖谁，所以实现上单独存一个标志，而不是把
值写进话题覆盖里去覆盖环境变量的结果。开关即时生效、重启保持。

## Status

accepted

## Considered Options

- **保留 `refresh_quality`，只在会员状态变化时重算**：被否。配置里仍然只有实际档位、没有意图，
  一旦写过就再也分不清「自动」与「手选无损」，重算与否都只能靠猜。
- **给音质字段记「谁定的」（用户 / 程序）**：推迟。值得做，但会改动公开配置格式，另开票。
- **重置或迁移已写在配置文件里的具体档位**：被否。旧版本写进去的值与用户手选的值在盘上无法区分，
  改写会覆盖用户真实的选择。
- **切档后立即重载当前曲并定位回原进度**：被否。成本与竞态不划算，主流客户端也不这样做。
- **区分降档原因（权益 / 单曲无该档位 / 网络 / 签名凭证）**：超出范围。需要上游接口提供能区分的
  信息，本仓库拿不到。
- **用「用户可见的一句话」代替日志详情开关**：被否。报障需要的是原始轨迹，不是又一句人话。

## Consequences

- 界面必须同时能表达「意图」与「实际」两个事实，且不能把它们混在同一个字段里：设置页讲意图，
  徽章讲实际。加新的音质 UI 时要守住这条。
- 缓存与权益解耦：非会员时期听过的歌在开通会员后仍播缓存档位。这是主流客户端的一致行为，
  已写进 README 与设置页说明；要拿到更高档位靠清空缓存或换意图。
- 旧缓存没有实际档位分数，因此升级后的第一次播放不会显示降档标记，直到该曲按当前意图重新取流。
  这是有意的：不知道就不能断言。
- `sodam-core::quality` 成为意图归一化、缓存标签与降档判定的唯一出处，且不依赖 GPUI，可离线单测。
- 详细日志开关只控制详细度，不提供「完全关闭日志」——至少错误级不可关，与 ADR 0002 一致。
