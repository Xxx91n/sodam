# #136 悬停残留 · 原型取证报告（prototype/136-hover-residue-probe 分支）

日期：2026-11-14 · 环境：Windows Server 20348 x64 · 被测对象：**发行版 sodam v0.3.8**
（`sodam-0.3.8-windows-x64-setup.exe`，SHA256 已对过 SHA256SUMS），DPI 96（100%），非最大化窗口 rect 462,189–1458,837。
本目录所有脚本为一次性探针，仅存在于本分支。

## 结论先行（对应交接的三个问题）

| 问题 | 答案 |
| --- | --- |
| **P1 鼠标离开后系统来问命中时框架答什么** | 框架的 `WM_NCHITTEST` 应答**完全不看查询坐标**。只要缓存的悬停状态是"关闭按钮"，窗口内任意点、窗口外任意点（实测到窗口外 145px）一律答 `HTCLOSE(20)`；仅顶部缩放边框两行（约 y=189–197）例外答 `HTTOP(12)`。中立状态下同样的点答 `HTCLIENT(1)` / `HTNOWHERE(0)` / `HTRIGHT(11)`。甩出窗口后该状态**至少 3.5 秒内不恢复**（实测上限），也不随时间自动消退。 |
| **P2 窗口外点击到底进没进 SodaM** | **没有进。** 窗口 rect 之外 15/60/200px 的点，`WindowFromPoint` 都指向别的窗口（本机是紧贴右侧的 WorkBuddy），系统不会把命中查询和点击发给 SodaM。窗口 rect 之内的点击则完全按当时状态走：按钮命中区内的点（按钮字形 ± 约 22px，关闭按钮一直延伸到窗口右缘）正常触发关/最小化/最大化；按钮区之外的点（如按钮下方 25px、顶部缩放边框行）即使用残留状态悬停后点击也**不触发按钮**（实测 6/6 无变化）。"窗口外点击触发按钮"在 v0.3.8 上**无证据**，与交接的预判一致。 |
| **P3 残留范围有多大** | 与距离和方向**无关**：三个按钮 × 右/上/右上 × 甩出 5/15/60/200px，普通窗口 36 组、最大化窗口 36 组，目标按钮残留全部亮（关闭红底 delta 182–212，min/max 灰底 delta 23–32）。个别"不残留"的样本是甩出点恰好落在相邻按钮上、相邻按钮合法点亮（属正常悬停，非残留）。最大化窗口时 rect 比可视区域四周大 8px（真不可见边框），但指针到不了屏幕外，无法点击。 |

一句话：**残留是"缓存的悬停状态 + 命中应答不校验坐标"造成的纯客户端缺陷；窗口外点击触发按钮这条在实测中不成立。**

## 补充观察（交接"顺手记录"项）

- 悬停正常路径没问题：从内容区移进标题栏、按钮间横移、从窗口外重新进入，悬停都会正常亮/灭（p1_reenter、p2b 各 case）。
- `WM_NCMOUSELEAVE` / `WM_MOUSELEAVE` 是否到达：**本轮没测到**。消息级捕获在本机不可行（见"方法与局限"），只能留给下一轮在能挂钩子的环境确认。
- 关闭按钮点击后窗口销毁、进程留托盘（`tray_icon_app`），再启动 exe 不会自动唤回主窗口——这是 v0.3.8 自身行为，与 #136 无关，取证时用它做过状态复位。
- 按钮的可视悬停底色区与命中区基本重合（红底块宽约 64px，一直延伸到窗口边缘）。

## 方法

没有 VS/Spy++/C 编译器，且本机（Server 20348）**拒绝一切跨进程线程钩子**（`SetWindowsHookEx` err=5，实测矩阵见 `tools/hook_matrix.ps1` 输出），注入式钩子在 .NET 4 上也走不通（vtable 导出路线，`tools/probe_hook.il`/`mini.il`，已放弃并留档）。最终仪器：

1. **合成 `WM_NCHITTEST`**：`SendMessageW(hwnd, 0x84, 0, MAKELPARAM(x,y))` 直接问 SodaM 的窗口过程并读返回值——系统悬停/点击时问的就是同一条消息、同一个窗口过程、同样的参数，因此返回值就是框架的真实应答。**对照实验证明合成查询不扰动画面**（连发 70+ 条前后截图像素 delta=0）。
2. **真点击 + 状态断言**：`SetCursorPos`/`mouse_event` 模拟悬停→甩出→点击，前后读 `IsWindow/IsIconic/IsZoomed/GetWindowRect`。
3. **像素取证**：按钮区 13×13 均值色 vs 无悬停基线，判定残留是否亮；全部截图存 `evidence/*.png`。

关键实验细节：甩出用单次 `SetCursorPos` 跳变（等价快速甩出的终态）；每个 case 前把光标移回内容区重置；点击前用合成查询记录当时应答，用于和结果对照。

## 方法与局限（必须知道的边界）

1. **消息级捕获没做成本轮的缺项**：系统真实派发的 `WM_NCHITTEST`（含时序）与 `WM_NCMOUSELEAVE` 到达与否无法在本机直接记录（无 Spy++/编译器、跨进程钩子被系统拒绝、IL 注入在 .NET 4 不可用）。合成查询在消息、窗口过程、参数上与系统查询一致，且行为级证据（截图+点击后果）与之互相印证，但"系统什么时候问、问了几次"仍属推断。
2. **DPI 只测了 100%**：125%/150% 需要改系统缩放（通常要注销），本机做不了，交接里的缩放矩阵未覆盖。
3. 只测了 Windows 发行版 v0.3.8；macOS/Linux 真机现象未验证（交接已定后置）。
4. 甩出用单次坐标跳变模拟；人手甩出会产生更多中间移动事件，但终态相同（最后一条窗内移动决定缓存），不改变结论方向。
5. 第一轮 P2 曾出现"残留态应答 HTCLIENT"的反常，定位为前一轮约 500 次合成查询污染了应用状态；重启进程后全部结果一致。已在报告数据中采用干净进程的复核结果。
